## 文字列の類似検索

- レーベンシュタイン距離は文字の並びの類似性を調べる
- トライグラムは共通する文字の組み合わせの類似性を調べる
- ベクトル検索は文字列の意味の類似性を調べる
- レーベンシュタイン距離は短い言葉でもいい、トライグラムは大量のデータから似た文字列を探す

gitのタイポと提案されるコマンド

- `git stauts`
  - 答え：status
  - 解説：ua → au の入れ替えはコスト 0。スコアは 1 で、最も近い
- `git pul`
  - A. pull だけ　B. pull と push　C. push だけ
  - 答え：B
  - 解説：pull は先頭一致でスコア 0。その次に近い push（置換1回でスコア 3…ではなく、pul→push は置換2＋挿入1＝3、スコア4）も一緒に表示される
- `git fetc`
  - A. fetch だけ　B. fetch と bisect　C. fetch と reset
  - 答え：B（ほぼ全員が外すと思います）
  - 解説：fetc → bisect は「f を s に置換（2）」「tc と ct の入れ替え（0）」「b, i を挿入（2）」で距離 4、スコア 5。入れ替えが無料で挿入が安いため、見た目が似ていない bisect が近くなる
- `git bisec`
  - A. bisect　B. bisect と reset　C. 何も出ない
  - 答え：C
  - 解説：bisect は先頭一致でスコア 0。しかし次に近い reset がスコア 7 で、しきい値の 7 以上になる。この場合、先頭一致した bisect まで表示されなくなる。1文字足りないだけなのに何も提案されない、というソースコードを読まないと分からない動き
- `git merg`
  - A. merge だけ　B. merge と grep　C. merge、grep、mktree
  - 答え：C
  - 解説：merge は先頭一致でスコア 0。次に近い grep と mktree がどちらもスコア 5 で同点なので、両方表示される
- `git wip`
  - 答え：diff、grep、help、init、switch の5つ
  - 解説：全部スコア 6 で同点。同点はすべて表示される
